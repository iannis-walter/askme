# Embeddings retrieval (Mistral) — design

**Date:** 2026-06-15
**Status:** Approved (design), pending implementation plan

## Goal

Replace the keyword + IDF retriever with semantic retrieval using Mistral
embeddings (`mistral-embed`), behind the **existing `Retriever` interface** so
the rest of the app is unchanged. This fixes vocabulary-mismatch failures
(e.g. "ML" vs "machine learning", French queries against English content) and
turns the app into a proper RAG — the single most on-message upgrade for the
Mistral application.

## Non-goals (YAGNI)

- Hybrid keyword+embedding retrieval or re-ranking.
- A vector database. The corpus is ~44 chunks; in-memory cosine is ample.
- Embeddings for non-Mistral hosted providers (Groq has none). Local dev keeps
  the keyword retriever.

## Interface contract (unchanged)

Both retrievers expose:

```
retrieve(query: str, k: int = 6) -> list[tuple[Chunk, float]]
```

`main.py` continues to call `STATE["retriever"].retrieve(...)`. No route or
schema changes.

## Components

### 1. `backend/embeddings.py`
- `embed_texts(texts: list[str]) -> list[list[float]]` — calls the Mistral
  embeddings endpoint (`https://api.mistral.ai/v1/embeddings`) in a single batch
  request. Model from `LLM_EMBED_MODEL` (default `mistral-embed`).
- `cosine(a, b) -> float` — similarity helper (vectors are L2-normalised once on
  load so cosine reduces to a dot product).
- **Pacing:** embeddings do NOT use the chat throttle (`LLM_MIN_INTERVAL_S`).
  Mistral's embedding limits are looser, and sharing the chat throttle would add
  ~1.1s per query. Optional `LLM_EMBED_MIN_INTERVAL_S`, default `0`.
- Reuses the provider config from `llm_client` (key, base URL derivation) where
  possible to avoid duplicated config logic.

### 2. Committed embedding cache — `backend/embeddings.json`
- Map: `f"{sha256(chunk.text)}:{model}"` → vector (list[float]).
- Content-hash keying makes the cache **self-invalidating**: editing a chunk in
  `content/` changes its hash; only that chunk is recomputed.
- Generated by a script `backend/build_embeddings.py` (run manually after editing
  content). The script loads documents, embeds all chunks in one batch, writes
  the JSON. Committed to git → baked into the Docker image → instant load on a
  Render cold start, **zero embedding calls at boot**.
- **Boot guard:** if a current chunk's hash is missing from the cache (forgot to
  regenerate), embed it on the fly at startup and log a warning. The committed
  cache should normally be complete.

### 3. `EmbeddingRetriever` (in `backend/retrieve.py`, alongside `Retriever`)
- Constructor takes `chunks` + the loaded cache; resolves each chunk's vector
  (from cache, or embeds missing ones once), stores normalised vectors.
- `retrieve(query, k)`: embed the query (1 call), cosine vs all chunk vectors,
  return top-k `(Chunk, score)` with `score > 0`. Same shape as `Retriever`.

### 4. Factory + fallback
- `build_retriever(chunks)` chooses based on `RETRIEVER` env
  (`auto` | `embeddings` | `keyword`, default `auto`):
  - `auto`: if `LLM_PROVIDER=mistral` and an API key is available → embeddings;
    otherwise (Ollama dev, no key) → keyword `Retriever`.
  - `embeddings` / `keyword`: force the choice.
- **Runtime fallback:** if a query embedding call fails in production, that
  request falls back to keyword scoring for the query — a recruiter never sees an
  error. (Keyword tokenisation/IDF is always built so the fallback is ready.)
- Called from the `lifespan` in `main.py` in place of the direct
  `Retriever(...)` construction.

## Configuration

| Env | Default | Purpose |
| --- | --- | --- |
| `RETRIEVER` | `auto` | `auto` \| `embeddings` \| `keyword` |
| `LLM_EMBED_MODEL` | `mistral-embed` | embedding model |
| `LLM_EMBED_MIN_INTERVAL_S` | `0` | optional pacing for embedding calls |

Local dev (Ollama, no key) → `auto` resolves to keyword, so nothing breaks and no
key is required. Production (`LLM_PROVIDER=mistral`) → embeddings.

## Data flow (prod)

```
build_embeddings.py (manual, on content change) → backend/embeddings.json (committed, baked)
boot: load docs → load cache → EmbeddingRetriever(normalised chunk vectors)
/chat: embed(query) [1 call, unthrottled] → cosine top-k → chunks → grounded prompt → chat completion
        (on embed failure → keyword fallback for this query)
```

## Error handling

- Missing/invalid embedding response at boot → embed-on-the-fly guard + warning;
  if the whole embeddings layer is unavailable → fall back to keyword retriever
  for the whole process (logged).
- Query embedding failure at request time → keyword fallback for that query.
- No silent truncation: cache misses and fallbacks are logged.

## Testing

- `cosine` correctness (orthogonal = 0, identical = 1).
- Cache load: a known hash maps to its vector; a changed text misses.
- `EmbeddingRetriever.retrieve` returns the expected source for a known query,
  using a **fake embedder** injected in the test (no network in CI).
- Factory: `auto` picks keyword without a key, embeddings with `mistral` + key.

## Deliverables

- `backend/embeddings.py`, `backend/build_embeddings.py`, `backend/embeddings.json`
- `EmbeddingRetriever` + `build_retriever` in `backend/retrieve.py`
- `main.py` lifespan uses `build_retriever`
- tests under `backend/tests/`
